The four-layer architecture, repo layout, and getting-started steps are correctly described in [README.md](../../README.md); see [knowledge/architecture.md](architecture.md) for the verified data-flow diagram.

## This is a patch/scaffold repo, not a deployable app

None of the four directories is a standalone runnable service:

- `dobase/` contains only Rails files meant to be **copied into** an external Dobase Rails application (per [dobase/README.md](../../dobase/README.md)) — there is no `Gemfile`, `config/routes.rb`, or `config/recurring.yml` here, only `config/routes_snippet.rb` and `config/recurring_snippet.yml` with merge instructions in comments.
- `twenty-apps/dobase-bridge/` is a starter layout to be merged into an app generated by `npx create-twenty-app@latest` — it is not itself bootable (no build config beyond `tsconfig.json`, and `twenty dev`/`twenty build` scripts assume a CLI that isn't part of this repo).
- `mcp-server/` is the only directly runnable piece (`python server.py` after `pip install -r requirements.txt`).
- `shared/design-tokens/` is a single CSS file to be copied/symlinked into both host apps.

When asked to "run" or "test" the `dobase/` or `twenty-apps/` layers, treat that as merging/reviewing patch code, not executing a live app — there's nothing here to boot.
